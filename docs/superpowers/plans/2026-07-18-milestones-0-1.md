# GrepNest Milestones 0-1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and prove the smallest authorized path from a fixture Git repository through real Zoekt to GrepNest REST and MCP search.

**Architecture:** `grepnest-server` owns authentication, authorization, canonical search, REST, and Streamable HTTP MCP. A Zoekt JSON adapter implements `SearchBackend`; `grepnest-mcp` is an authenticated stdio proxy to the hosted MCP endpoint.

**Tech Stack:** Go 1.26, Go standard library, `log/slog`, official MCP Go SDK v1.6.1, Prometheus client v1.23.2, Zoekt `3c8b39b1ef4f8194cb912d7e6581cff9db224aa7`, Docker Compose.

## Global Constraints

- Implement Milestones 0 and 1 only; no GitHub App, PostgreSQL application integration, OpenShift, Helm, file reads, or outlines.
- Module path is temporarily `github.com/grepnest/grepnest` because no Git remote exists.
- No Java or JVM runtime, build tool, sidecar, or service.
- Zoekt is internal; only `grepnest-server` may call it.
- All repository authorization is server-selected and passed with Zoekt's dedicated `RepoIDs` field.
- Clamp limit to 100, context lines to 20, timeout to 5 seconds, and normalized response to 256 KiB by default.
- Use argument arrays for subprocesses; never execute fixture repository code.
- Pin dependencies, actions, and images; never use a `latest` tag.
- Each task follows red-green-refactor and ends with an atomic signed commit of 72 characters or fewer.
